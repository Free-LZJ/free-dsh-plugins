# 规则维护规范

**何时加载**：新增、修改、删除、拆分 `AGENTS.md` 或 `rules/*.md` 时；某条规则在实现里被绕过（出了本该拦住的错误）需要修正时。

规则分层：

| 层 | 位置 | 内容 |
|---|---|---|
| 索引 | 根 `AGENTS.md` | 只写项目结构、阅读顺序、规则与文档索引；**不写任何具体约束** |
| 规则 | `rules/*.md` | 可执行约束，一个文件一个主题，头部声明何时加载 |
| 文档 | `docs/**` | 背景、设计、操作手册等参考信息，不是约束 |

## 新增规则

- 一条约束只能有一个权威位置。`AGENTS.md`、包 README、`rules/` 之间不得重复维护同一句话；发现有重复，删掉较远的那份并指向权威位置。
- 每条规则文件头部第一句必须是 `**何时加载**：…`，写清**触发动作**（不是"开启某功能时"这种宽泛说法），让 agent 不必读全文就能判断该不该读。
- 规则要可机械判断。"代码要清晰"不是规则，"新增依赖前先查 `package.json` 是否已有等价能力"才是。
- 只有跨仓库复用的行为才写成 skill；本仓库约束留在 `rules/`。

## 修改与删除

- 改规则前先读对应的最近 `AGENTS.md` 与被改规则的同主题文件，确认不放宽任何已有约束（本仓库只有根级规则，不存在子目录放宽的情况）。
- 规则调整后至少检查：索引链接可解析、`**何时加载**` 行仍在首句、与代码现状一致。
- 规则被违背过的，除改写文本外要留下最小检查（见 [`testing.md`](testing.md)）；只改文字、不加检查，视为未修复。
- 删除规则时同步删除 `AGENTS.md` 索引里对应的一行；留下悬空链接等同于没有索引。
