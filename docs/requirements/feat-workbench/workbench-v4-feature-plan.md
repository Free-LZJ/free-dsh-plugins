## 0. 一句话诊断

v3 做完了「**邮件 → 会话**」，没做「**会话 → 可验收的结果**」。

工作台现在是个转发器：邮件进来、规则判一下、起个会话、把 agent 的碎句贴回来、会话一结束就把卡标成
「已处理」。人没法判断**这件事到底办成了没有**，也没法在 agent 半路提问时给出回答（刷新页面就丢）。
所以「勉强跑通」不是缺面板，是缺后半截。

## 1. 实测现状（2026-11-02，取自 `~/.dsh/dsh-console/`）

| 项 | 实测值 | 说明 |
|---|---|---|
| 卡片 | 10 张：9 `done`、1 `running` | `done` 只代表会话的 `turn/end` 到了 |
| 派发后的可见内容 | 每条会话 11 行左右、截断 1200 字的助手文本 | 内容是 agent 的自言自语，例如 “Checking whether any `package.json` changed…” |
| 注意力队列 | 2 条 `new` 挂了 2 天 | 其中 GitHub CI 那条**同时**是 `processing` 卡，同一件事占两个位子 |
| 卡片分类 | 3 张全是 `kind=unknown`、`classification=[]`、`confidence=1` | 假 100% 置信度，比没有更糟 |
| 规则文件 | `rules.yml` 297 行（含 YAML 锚点与模型标签词典） | UI 只能改列表型条件值、开关、排序 |
| 改规则的方式 | 「复制修复指令」→ 交给 agent 去改文件 | 用户原始需求是「规则会经常改」 |

## 2. 说法对照（本文一律用右列的说法）

| 容易看不懂的说法 | 实际指的是 | 用户会看到什么 |
|---|---|---|
| 状态机列 | 看板多一列「待验收」 | agent 说干完了先停在这一列，你看一眼才进「已处理」 |
| 持久化审批 | agent 的提问存在 Host 那边 | 关掉页面再打开，问题还在、agent 也没死 |
| 批量审批 | （结论：不做）改成低风险自动放行 | 不用一次勾二十个，改成「这种活以后别问我」 |
| review 列 | 同上「待验收」 | —— |
| HITL | 「人和 agent 交接的地方」 | 所有「它问你、你回它」的界面 |

## 3. 开源调研结论

调研对象：OpenClaw 生态（含 openclaw-nerve）、langchain agent-inbox、Letta、OpenHands、Goose、
Agent Zero、Personal_AI_Infrastructure、inbox-zero、agentmail；自动化侧：n8n、Windmill、Kestra、
Node-RED、Activepieces、Plane、Zapier、Gmail filter、Temporal。

### 3.1 要的（按进入工作台的顺序）

| # | 功能 | 来源 | 解决我们的哪个实际毛病 | 成本 |
|---|---|---|---|---|
| 1 | **提问不丢**：agent 的待答问题落盘到 Host，重连能捞回来 | Letta `recoverPendingApprovals`、agent-inbox | 刷新页面 agent 永久卡在「等你」 | 中 |
| 2 | **待验收列**：跑完不直接算完成，人点「通过 / 打回」 | openclaw-nerve 的 `review` 列 | `done` 是假 done，看不出办成没 | 低 |
| 3 | **产出摘要**：卡片上直接给「结论一句话 + 改了哪些文件」 | 实测缺口（无外部来源） | 现在只有截断的独白 | 中 |
| 4 | **四种回答**：同意 / 改一下再同意 / 回一句话 / 忽略 | agent-inbox 四动词 schema | 现在只有「插话一句」和「停」 | 低 |
| 5 | **介入档位**：全自动 / 只问高风险 / 全问，每会话可切 | Goose 四档、OpenHands `ConfirmRisky` | 不知道什么时候该管，全变成待办 | 低 |
| 6 | **拒绝理由回灌**：打回时写一句，喂回给 agent | OpenHands `reject_pending_actions` | 同一个错反复等你点拒绝 | 低 |
| 7 | **规则三段式摘要**：「当 X 且 Y，则做 Z」，摘要和表单同源 | Plane `When/If/Then` | 改规则要读懂 297 行 YAML | 中 |
| 8 | **表单编辑 + 原文旁挂**：默认表单，YAML 作为同步的旁挂视图 | Kestra Form/Source | 同上 | 中 |
| 9 | **未命中原因**：规则没触发时说清卡在哪个条件 | 调研共识（90% 的困惑来源） | 「为什么这封邮件没被处理」 | 低 |
| 10 | **提议箱**：agent 只能「提议」建卡/改卡，人批准才落地 | Nerve 的 markers + proposal | agent 发现了相关的事但没权限落看板 | 中 |
| 11 | **邮件即审批**：手机上回 `approve` / `defer 7d` / `edit: …` | agentmail approval-inbox | 不想开电脑也能批 | 低 |

### 3.2 明确不要的

| 不要 | 理由 |
|---|---|
| 节点画布（n8n / Node-RED） | 邮件→会话只有 2–3 步，画布把屏幕留给了空白。问题是缺语义，不是缺图形 |
| 舰队式全能工作台（Nerve 的语音/TTS/编辑器/主题，Agent Zero 的整台桌面） | 加面板只增维护面，不减抱怨 |
| 5 秒轮询同步 | Host 与浏览器本来就有事件通道；抄轮询会让「卡住」变常态并掩盖真断线 |
| 「一句话生成整条规则」 | Activepieces 自己踩过并回退：难点在账号与字段，不在结构 |
| UI 批量审批 | 查遍 Nerve / agent-inbox / Letta / OpenHands / Goose，没有一家做多选批处理；正解是把批量前移到规则层（低风险自动放行） |
| 给每个动作都加确认按钮 | 会把工作台变成盖章机，见 §3.1 #5 |

## 4. 分期

每期独立可交付、可本地实测；上一期不做完不进下一期。

### P1 闭合「跑完之后」（先做这个）

解决的问题：不知道 agent 到底办成了没有。

1. agent 的待答问题落盘，页面重连能捞回来（#1）
2. 看板加「待验收」列：`turn/end` 后先进这一列（#2）
3. 卡片产出摘要：结论一句话 + 改了哪些文件（#3）

验收：拿一封真实邮件跑一遍 → 会话结束后卡停在「待验收」→ 卡片上能读到结论与改动文件 →
点「通过」才进「已处理」→ 中途关掉页面重开，待答的问题还在。

### P2 让「人介入」好用

解决的问题：它问你的时候，你只有两个按钮。

1. 四种回答方式（#4）
2. 介入档位：全自动 / 只问高风险 / 全问（#5）
3. 打回时写一句理由，喂回 agent（#6）

验收：同一个任务分别在三种档位下各跑一次，确认弹出的问题数量与档位一致；打回一次，
agent 的下一轮能读到那句理由。

### P3 让「配置」好用

解决的问题：改一次规则要开文件、读懂 YAML。

1. 三段式摘要句，摘要与表单同源（#7）
2. 表单编辑为主，YAML 作为旁挂视图（#8）
3. 规则没触发时说清卡在哪个条件（#9）

验收：不改任何文件，只用界面新增一条规则并让它命中一封测试邮件；故意让一条规则不命中，
界面能说出卡在哪个条件。

### P4 让 agent 主动

解决的问题：它发现了相关的事，但只能写在聊天里。

1. 提议箱：agent 只能提议，人批准才落地（#10）
2. 邮件即审批通道（#11）

验收：让 agent 提议建一张卡 → 卡片不出现、提议出现 → 批准后才出现；用邮件回 `defer 7d`
确认提议被推迟。

## 5. 待验证的技术前提

写实现方案前必须先确认，否则又是「猜 API」：

- [ ] `session/event` 里除 `assistant/message`、`turn/end` 之外，还有哪些事件类型可以用
      （工具调用、文件改动）。当前 checkout 是 asar 包，源码不可读，需要在运行中的宿主里打点确认。
- [ ] 「待答问题」在宿主里有没有现成的表达（`permission/preset` 事件？`turn/end` 的 reason
      是否区分 `awaiting-input`）。若没有，P1 #1 要自己在 Host 侧建一张待答表。
- [ ] `review` 列加入后，`awaitingConfirmation` 这个旧字段是废弃还是复用（现在只被
      `CardDetail` 的「确认」按钮使用）。
