# @free-lzj/dsh-worktree

Git 工作树管理：一页列出按**仓库**分组的工作树，可配置检出放哪、创建前要不要拉上游；会话标题栏和空会话首屏各有一个「工作树」按钮，直接在那个检出里开会话。原检出、原分支都不动。

## 安装

```bash
dsh plugin --profile web add @free-lzj/dsh-worktree
```

装完重启 dsh（Host 半边带路由，只在启动时加载）。插件插入一行 Loader 行 `worktrees`。

## 工作树管理页

侧边栏的 **工作树** 入口（分支图标）打开主面板，从上到下：

**设置卡片**

| 项 | 说明 |
|---|---|
| 工作树目录 | 留空 = 每个仓库自己的 `.agents/worktrees`；填绝对路径则每个仓库在其下建一个同名子目录（`<目录>/<仓库名>/<名字>`），跨仓库不会撞名 |
| 创建前拉取上游更新 | 开启后先 `git fetch --all --prune`，新分支从当前分支的上游（`@{upstream}`）起；没配上游或拉取失败时退回本地 `HEAD`，不会因此失败 |
| 保存 | 写进 `~/.dsh/worktree/settings.json`，即时生效，不需要重启 |

**按仓库分组**

每个注册过工作区的 Git 仓库一张卡片：仓库名、完整路径、工作树数量、`新建`。卡片里每行是一个检出：

| 列 | 内容 |
|---|---|
| 分支 | 分支名；`主检出` / `已锁定` 标签；分离头显示 `（分离头）` |
| 路径 | 相对仓库的路径 + 短 commit |
| 进入 | 在那个目录里打开（或复用）会话 |
| 删除 | 两段确认（3 秒内再点一次）：删检出 + 删分支，并一并删掉它的工作区注册 |

同一个仓库的多个检出只会出现一张卡片（按 Git 的共享 `.git` 归并），不会因为注册了多个检出目录而重复。

## 会话标题栏的入口

**任何会话**的标题栏右上角有 `工作树` 按钮；空白新会话首屏那一行也有一个。点开是新建对话框：填名字（留空自动生成 `worktree-xxxxxxxx`），`创建并开始` 就在新检出里开会话。`管理` 跳到上面的管理页。

### 检出放在哪

```text
默认： <仓库根>/.agents/worktrees/<名字>
配置： <工作树目录>/<仓库名>/<名字>
```

默认布局与官方实验 bundle `@deepseek-ai/dsh-experimental-worktree` **完全一致**，两个插件可以同时装（Loader 行 id 分别是 `worktrees` 与 `worktree`）。想让它显示成仓库下的子工作区：侧边栏 `视图选项 → 分组方式 → 按工作区树`。

## 行为与约定

| 事项 | 现在的行为 |
|---|---|
| 起点 | 当前分支的上游（开启拉取时）或本地 `HEAD` |
| 名字 | 字母、数字、点、下划线、短横线，最长 64；同名分支或目录已存在时报错，不覆盖 |
| 复制内容 | **只复制已提交内容**。暂存、未暂存、未跟踪、被忽略的文件都不带过去 |
| 删除边界 | 删任何 Git 已注册的检出，不论它建在 `.agents/worktrees`、仓库旁边还是别处；仓库主检出与 Git 锁定的检出拒绝 |
| 删除保护 | 有本地改动或子模块未初始化的由 Git 自己拒绝，原因原样返回 |
| 权限 | 沿用 Host 进程自己的文件权限；不额外申请沙箱权限 |

## 已知限制

- **不合并、不 rebase**：工作树里的分支怎么合回主干，是 `git merge` / MR 的事。
- **不装依赖**：新检出是干净树，需要 `pnpm install` 之类由你或 agent 在会话里做。
- **一个会话一个目录**：`进入` 不会搬动当前会话，而是**新开**一个。
- **只认注册过的仓库**：管理页的仓库来自 dsh 的工作区注册表，不是扫盘；没注册过的仓库不会出现（先在侧边栏「添加工作区」）。
- **盘根不算仓库**：某个盘符根目录里有 `.git` 时 Git 会把下面所有目录都认成那个仓库，本插件直接拒绝这种解析。

## 开发备注

**为什么 `tsconfig.json` 里有 `paths`**：本包开发依赖钉在 0.2.x 预发布，而仓库其他包仍构建在 0.1.x，pnpm 因此会链接两份 `@deepseek-ai/cordis` / `dsh-client-ui-slots`。模块增强（`ctx.slots`、`ctx.locale`、`SlotMap`、`LocaleNamespaceMap`）只并入**同一份物理模块**，指错副本的症状是 `Property 'slots' does not exist on type 'Context'`。`paths` 把两侧都指向本包自己那一份，即本包 peer 实际运行的那一版。等仓库整体升到 0.2.x 后可以删掉。

**为什么 Git 走 `node:child_process`**：本包不依赖 harness 的 `subprocess` 服务，少一层装配；参数全部是本模块拼的字面量，没有 shell 插值。需要更严格的进程策略时再接 `subprocess`。
